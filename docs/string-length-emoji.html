Why is the length of an emoji 2 in JavaScript?

Because String.prototype.length counts UTF-16 code units, not characters. Most emoji need two code units, and many are sequences of several code points. To count what a person sees, count grapheme clusters with length(str) from graphemely.

The fix, copy and paste

Emoji in the code samples are written as JavaScript escapes, for example \u{1F468} for a man. In your own code you can type the emoji directly.

What .length actually measures

The spread operator and Array.from iterate by code point, which fixes surrogate pairs but still counts every part of a sequence. Only grapheme segmentation, as defined by Unicode UAX #29, matches what users see.

Where this bites in real code

  • Character counters on text fields that disagree with what the user typed.
  • Validation like "username must be at most 20 characters" that rejects short names with emoji or accents.
  • Fixed width layouts and tables where padding is computed from .length. See padStart and padEnd in graphemely.

Note that some limits are defined in bytes or code units on purpose, for example database column sizes. Use .length or new TextEncoder().encode(str).length for those, and length(str) for anything a human reads.

Install

Works in Node 16 and newer, all modern browsers, Deno and Bun. ESM and CommonJS, TypeScript types included, zero dependencies, about 2 kB gzipped. Try your own text in the playground.

FAQ

JavaScript strings use UTF-16. Emoji live outside the Basic Multilingual Plane, so each one is stored as a surrogate pair of two code units, and .length counts code units.

It is three emoji (man, woman, girl) joined by two zero width joiners: 2 + 1 + 2 + 1 + 2 code units. It displays as one character, which is one grapheme cluster.

It counts code points, which is better than code units but still wrong for emoji sequences, flags, skin tones and combining accents.

Count grapheme clusters: length(str) from graphemely, or Intl.Segmenter with granularity grapheme.
